| **BUG-032** | **A push runs the full gate, reports nothing wrong, and pushes nothing — `git push` dies of SIGPIPE after the gate succeeds.** Seven occurrences on 2026-08-19, each costing a ~361 s gate. **Signature, measured:** `git push` exits **141** (`128 + 13` = SIGPIPE), the gate prints `PASSED`, there is no `To github.com:` line, and `git ls-remote` shows the ref absent. **A re-run is NOT a workaround** — it appeared to be one for the first five, then failed twice consecutively on an unchanged branch, which is what made the mechanism testable. **Mechanism — CONFIRMED by experiment:** git contacts the remote for its ref state *before* running `pre-push` — that is how it fills the `<remote sha>` field the hook reads on stdin — then the gate holds the connection idle for ~361 s, then git writes to a socket the server has since closed. **The proof:** after two consecutive failures on an unchanged branch, the identical push with `GIT_SSH_COMMAND="ssh -o ServerAliveInterval=20"` landed first try, exit 0. Nothing else differed. The intermittency is the gate sitting on a ~5-minute idle boundary. **This is TASK-013's re-open trigger firing** — *"the gate crosses an interval that changes behaviour"* — just not the behaviour predicted (nobody started skipping the hook; the push started dying). The two items should be read together. **Half of the original description was measurement error and is corrected here:** the handover recorded this as *"a push can report success"*. It never reported success — the usual invocation is `git push … 2>&1 | tail -N`, and **a pipeline's exit status is the last command's**, so the `0` came from `tail` and was never evidence about git. The vanished push is real; `git ls-remote` is the only authority. **Not the fix:** `--no-verify` (denied by policy, and it defeats the gate), or retrying blindly (it works, but pays a full gate per attempt). **Candidate fixes, in order of preference:** get the gate under the idle boundary (TASK-013 — `bootstrap-gate` alone is 50.6%); set an ssh `ServerAliveInterval` so the connection is not idle; or run the gate out-of-band and leave a short hook on the push path. **Reproducer needed before any fix:** a hook that sleeps past the boundary, asserting the push still lands — without it there is no way to tell a fix from a lucky run. | S2 | KEEP | Raised 2026-08-19 after five occurrences in one session.
