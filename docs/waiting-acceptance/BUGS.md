| **BUG-014** | A test suite writes commits and config into the repository under test, disarming the gate | S1 | **FIXED 2026-08-02** — reported by linkedin-watcher-agent ([PR #4](https://github.com/LuizStruct2Flow/blueprint/pull/4)), reproduced and fixed here | Git exports `GIT_DIR` to every hook. The pre-push gate runs the suites, so all of them inherit it — and thirteen build fixtures with `( cd "$WORK" && git init && git add . && git commit )`. **`cd` protects nothing**: with `GIT_DIR` set git ignores the working directory entirely and operates on the directory that variable names, so the fixture's commit lands in the REAL repository. Reproduced in seconds: `GIT_DIR=/tmp/victim/.git bash tests/marker-merge/test.sh` moved the victim's HEAD `43c2949 → 54a4d6f`. **This closes the open question on BUG-004** — that row records `.git/config` rewritten at 12:40:15 with `core.bare=true` and `core.hooksPath` wiped by "an unrelated process it could not identify". It was these suites. The suite that exists to prove the gate arms is what disarmed it, and the ungated push of `fdae0e2` follows directly. **Fix, two layers:** `.githooks/pre-push` strips `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE`/`GIT_OBJECT_DIRECTORY` once at the source (safe — git runs hooks from the repo top level, so discovery from cwd finds the same repository), and all 13 fixture-building suites strip them individually so a suite is safe run from any other hook context. Regression: [`tests/git-isolation/`](../../tests/git-isolation/test.sh), in the gate and CI. **A near-miss worth recording:** my first reproducer exported `GIT_DIR` *and* `GIT_WORK_TREE` and passed — setting both changes git's behaviour and the fixture stops landing in the victim, so the test would have gone green against unfixed code. Git hands a pre-push hook `GIT_DIR` alone. **Their original report, kept because it is evidence I could not have produced:** the defect surfaced when pushing a branch from a `git worktree` — `tests/marker-merge/test.sh:92` landed its fixture commit *on the branch being pushed*, reflog-confirmed six seconds after theirs, tree replaced, the push then failing with `path '.githooks/pre-push' exists on disk, but not in 'HEAD'`. They flagged the `GIT_DIR` attribution as inferred rather than proven; the reproduction here proves it. **This is also why [PR #3](https://github.com/LuizStruct2Flow/blueprint/pull/3) flagged its own worktree recipe as unsafe — that gap is this bug, and it is now closed.** |
